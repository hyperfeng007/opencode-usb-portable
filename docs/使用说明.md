# OpenCode 便携版（U 盘版）使用说明  v1.1.5

插上 U 盘就能用的 opencode 桌面版：**所有数据都在 U 盘上，拔盘后 Windows 里不留任何东西。**
本包自带"首次构建器"——因为完整程序解压后接近 500 MB，超过可打包分发的大小，所以改为**第一次在 U 盘上自动联网装好**（首次可以慢一点）。

版本：1.1.5 ｜ 目标系统：Windows 10 / 11（64 位）｜ 首次安装需联网

> **v1.1.5 变更：默认只在"完全不需要 key"的免费模型里挑**
> 从本版开始，启动时**不再要求你注册任何账号**：启动器只在免 key 的免费模型中选择
> （内置的公开免 key 接口 + 本机 Ollama / LM Studio 等），并验证它真的能调用工具，然后写进 opencode 配置。
> 想改用需要 key 的来源（OpenCode Zen、智谱、OpenRouter…）：把 `data\model-policy.json` 里的
> `keylessOnly` 改成 `false` 即可。详见「三之二」。
>
> **v1.1.4 新增：每次启动自动检测并切换免费模型**
> 启动时会自动体检你配置的免费模型：**能用的继续用，下架/限流/失效的自动换成另一个能用的免费模型**，
> 并把结果写进 `data\models-report.json`。详见第三节之后的「免费模型自动检测」。
>
> **v1.1.3 新增：启动进度窗口**
> 双击 `OpenCode-Portable.exe` 后会立刻出现一个进度窗口，实时显示当前在做哪一步、已完成百分比：
> 检查环境 → 查询版本 → 下载 opencode（按字节实时百分比）→ 解包 → 便携化改造 → 重建归档（按文件数实时推进）
> → 校验 → 启动 opencode → **等 opencode 窗口出现后，进度窗口自动关闭**。
> 已装好时它只短暂显示"正在启动 opencode / 正在等待 opencode 窗口"，几秒内消失；
> 窗口内的小字会说明这一步在做什么、能不能拔盘；失败时进度条变红并弹窗给出原因。
>
> **v1.1.2 修复（针对"还是闪退"）**
> 1. **启动器不再调用 `.cmd` 文件**，而是直接启动 `tools\OpenCode-Portable-Builder.exe`。
>    之前"一闪就没了"的根源是批处理调用（引号转义 + 批处理解析），现在这条路径整个消失。
> 2. **双击去重**：安装过程中再次双击不会再开第二个构建（你的日志里出现过两个构建进程并行抢同一个缓存），
>    现在第二次双击会弹提示"正在安装中"，并指向 `data\build.log`。
> 3. **失败绝不再无声退出**：构建器失败时控制台会停住等你按回车，同时启动器弹出对话框写明原因
>    ＋日志尾部；状态另写入 `data\build-state.json`。
> 4. **构建器自己的下载也会走系统代理**（之前只有启动器走代理）。
> 5. **直连 GitHub 失败会自动改走公共镜像**重试，内容仍按官方 SHA-256 校验（`--no-mirror` 可关闭）。
> 6. 修复了便携引导脚本（注入到主程序的那个模块）**缺少 `import`** 的严重缺陷——该缺陷会导致
>    便携模式静默失效（数据写回宿主 C 盘），现在已修复并在实测中确认数据全部落在 U 盘。
> 7. 三个 `.cmd` 全部重写为 **CRLF + 纯 ASCII + 无 goto/无括号文本**，并在 Wine 的 cmd 里实测通过。

## 一、三步开始用

### 第 1 步：把本包内容复制到 U 盘根目录（或任意文件夹）

解压后应该长这样（`OpenCode\` 目录此时还不存在，是首次构建生成的）：

```
X:\
├─ OpenCode-Portable.exe            ← 启动器（双击就用它）
├─ Build portable version.cmd       ← 手动首次构建（可选，联网只跑一次）
├─ Update OpenCode.cmd              ← 以后更新 opencode 版本
├─ OpenCode-debug.cmd               ← 出问题时用它看日志
├─ OpenCode-Portable.json           ← 便携标记（别删）
├─ 使用说明.md                      ← 本文件
└─ tools\
    ├─ OpenCode-Portable-Builder.exe  ← 构建器
    └─ 7za\7za.exe                    ← 解包工具（1.3 MB）
```

### 第 2 步：双击 `OpenCode-Portable.exe`

**只需要双击它，剩下全自动**（并会显示一个进度窗口，说明当前正在做什么）：

- 如果 U 盘上还没有 opencode 主程序 → 自动开一个控制台窗口，联网下载官方 opencode 桌面版
  （约 120 MB）→ 解包 → 完成便携化改造 → **装完自动启动 opencode**。
- 如果已经装好 → 直接启动，不下载任何东西。

首次安装需要 **≥ 2 GB 空闲空间**，几分钟（取决于网速与 U 盘速度）。
进度窗口里的文案会依次变成：

| 进度窗口显示 | 正在做什么 | 大约耗时 |
|---|---|---|
| 正在检查环境 | 定位 U 盘根目录、准备目录 | 1 秒 |
| 正在查询 opencode 版本信息 | 问 GitHub 要版本号（走代理/镜像） | 1–3 秒 |
| 正在下载 opencode 安装包 | 下载约 120 MB，**按字节显示真实百分比** | 取决于网速 |
| 正在解包应用（约 500 MB） | 用内置 7za 解包到 U 盘 | 20 秒–几分钟 |
| 正在做便携化改造 / 正在重建应用归档 | 打补丁并重建 app.asar，**按文件数推进** | 10–60 秒 |
| 正在校验新归档 | 校验新归档完整性 | 1–2 秒 |
| 正在启动 opencode / 正在等待 opencode 窗口 | 启动 opencode，等它的窗口出现 | 3–10 秒 |

opencode 窗口出现后，进度窗口会自动关闭；如果 90 秒内还没等到窗口，它会自行退出，不会一直挡着屏幕。
构建过程同时写入 `data\build.log`（详细日志）和 `data\build-state.json`（状态：starting/running/ok/failed），
即使控制台被关掉也能回看进度和错误。

> 也可以手动双击 `Build portable version.cmd` 安装：它会问你要不要顺便装便携版 Git。
> 自动模式默认装 Git；不想装就设环境变量 `OPENCODE_PORTABLE_SKIP_GIT=1`。

## 二、它在 U 盘上做了什么

| 位置 | 内容 |
|---|---|
| `OpenCode\` | opencode 主程序（首次构建生成，可随时用 `Update OpenCode.cmd` 更新） |
| `data\userdata\` | 会话、配置、数据库、窗口状态、崩溃转储 |
| `data\config\` `data\cache\` `data\state\` | opencode 的 XDG 目录 |
| `data\home\` | HOME（插件、终端里 `~` 指向这里） |
| `data\tmp\` | 临时文件（原本会在 `%TEMP%`） |
| `data\launcher.log` | 启动器日志（含检测到的代理、路径、错误） |
| `data\build.log` | 构建日志（首次安装/更新全过程） |
| `data\build-state.json` | 构建状态（用于"正在安装中"判断与失败原因） |
| `data\cache\build\` | 下载的安装包缓存（重装/换版本时免重复下载，可删） |
| `data\model-policy.json` | 模型策略（keylessOnly、是否自动切换、优先级、自定义来源） |
| `data\models-report.json` | 每次启动的模型体检结果 |
| `data\backup\` | 改动 opencode 配置前的自动备份 |
| `version.json` | 构建信息（版本、时间、校验值） |

**拔盘无残留的原理**：启动器在启动前就把所有可写位置重定向到 U 盘（`userData`、`sessionData`、`XDG_*`、`HOME`、`TMP/TEMP`、`APPDATA`、`LOCALAPPDATA`），主程序补丁还做了三件事——关闭自动更新（绝不在宿主机装 NSIS 安装包）、不写 `opencode://` 注册表关联、`userData` 强制走 U 盘。另外主进程内置"残留台账"：每次启动/退出都会检查宿主机上是否出现了**本程序自己创建的**痕迹并清理（只删自己的，绝不碰你原有的目录）。

实测（Wine 模拟 Windows）：构建并运行后，宿主用户目录内**没有任何 opencode 相关文件**，会话/配置/日志全部出现在 U 盘的 `data\` 下。

## 三、自动使用系统网络代理

**启动器和构建器都会自动读取代理**，按顺序尝试：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | 已有 `HTTP_PROXY`/`HTTPS_PROXY` | 你已设置的不覆盖 |
| 2 | 命令行 `--proxy http://127.0.0.1:7897` | 构建器专用 |
| 3 | WinINET 系统代理 | 设置 → 网络和 Internet → 代理 |
| 4 | WinHTTP / IE 配置（含 PAC 地址） | 企业环境 |
| 5 | **注册表直读** `ProxyEnable`+`ProxyServer` | Clash / v2rayN / sing-box / Proxifier 写的就是这里 |
| 6 | PAC 脚本 / WPAD 自动检测 | 开启"自动检测设置"时向系统要真实代理 |

支持 Windows 的三种写法：`127.0.0.1:7897`、`http=…;https=…`、`socks=…`（自动转成 `socks5://`）。
注入的变量：`HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`（自动含 `localhost,127.0.0.1,::1`），Node、Git、内嵌服务端全部生效。

**直连 GitHub 失败时**，构建器会自动改用公共镜像重试（`https://ghfast.top/` → `https://gh-proxy.com/`），
下载内容仍按官方 SHA-256 校验，日志里会写明"本次通过公共镜像下载"。想强制自定义镜像：

```
set OPENCODE_PORTABLE_MIRROR=https://ghfast.top/
```
关闭镜像回退：`--no-mirror`。关闭代理注入：`OPENCODE_PORTABLE_DISABLE_PROXY=1`。
如果是 TUN/全局模式（不需要代理注入），关掉也没关系。

## 三之二、免 key 免费模型（默认）与自动切换

启动器**每次启动**都会先做一次"模型体检"，默认**只使用完全不需要 API key 的免费模型**：

| 来源 | 说明 | 是否需要 key |
|---|---|---|
| **内置公开免 key 接口**（Pollinations.AI 匿名层） | 默认来源，实测可用（gpt-oss-20b 级别，支持工具调用，128k 上下文） | ❌ 不需要 |
| **本机 Ollama** | 检测到 `127.0.0.1:11434` 有服务就自动加入候选，无限量、离线可用 | ❌ 不需要 |
| **本机 LM Studio / llama.cpp / Jan / vLLM / SGLang / GPT4All / KoboldCpp** | 原理同上，检测到就加入 | ❌ 不需要 |
| 你自己的免 key 接口 | 在 `data\model-policy.json` 的 `keylessProviders` 里追加 | ❌ 不需要 |
| OpenCode Zen / 智谱 / ModelScope / iFlow / OpenRouter / 硅基流动… | **需要 key**，默认不参与选择（把 `keylessOnly` 改成 `false` 才会用） | ✅ 需要 |

每次启动的顺序：

1. 查找可用来源：内置免 key 接口要能拉到模型清单；本机服务要真的能应答（1.5 秒超时）；
2. 排序"好用"：支持工具调用 > 代码模型 > 上下文大 > 来源可靠（本机无限量 > 公共接口）；
3. **发真实的最小请求**确认能通（走系统代理，公共接口也支持代理）；
4. **验证工具调用能力**：让模型真的触发一次工具调用 —— 这是 opencode 能读写文件、执行命令的前提；
5. 结果分三种：
   - 当前模型能用 → **什么都不改**（实测 100–600 毫秒）；
   - 当前模型失效（下架 / 限流 / 没 key / 超时）→ 自动写入 provider 定义 + `model`，**原配置先备份**到 `data\backup\`；
   - 一个都用不了 → 不改配置，报告里写清原因和下一步。

### 结果在哪里看

| 文件 | 内容 |
|---|---|
| `data\models-report.json` | 本次检测明细：`action`（kept/switched/…）、`keylessOnly`、每个候选的探测结果与耗时、工具调用验证结果、配置备份路径 |
| `data\launcher.log` | 人类可读小结：`免 key 来源 : Pollinations… 可用，1 个模型`、是否切换等 |
| 进度窗口 | 检测时显示"正在查找免 key 的免费模型"、"正在验证工具调用能力（…）" |

### 说明与限制（重要）

- 公共免 key 接口是**共享匿名额度**：可能被限流（返回 429），也可能某天调整策略。启动器每次启动都会重新检测，
  失效时自动换到本机模型或提示你，但**无法保证公共接口永远可用**。
- 最稳的免 key 方案是**本机模型**：装了 Ollama 并 `ollama pull qwen3-coder:30b` 之后，启动器会自动用它（无限量、不怕限流、不联网也能跑）。
- opencode 首次使用这个自定义 provider 时，会自动从 npm 拉取 `@ai-sdk/openai-compatible`（需要联网一次，之后缓存在 U 盘）。
- 默认的公共接口不带 `limit` 之外的能力（不支持图片附件），纯文本 + 工具调用是够用的。

### 常用配置（`data\model-policy.json`，首次运行自动生成）

```jsonc
{
  "keylessOnly": true,          // 默认：只在免 key 的免费模型里选
  "disableBuiltinKeyless": false, // true = 不用内置公开接口，只用本机模型
  "autoSwitch": true,           // false = 只检测、不改配置
  "pinnedModel": "",            // 固定用某个模型，如 "ollama/qwen3-coder:30b"
  "excludedModels": [],
  "toolCheckCandidates": 3,     // 最多验证几个候选的工具调用能力
  "maxProbeCandidates": 6,
  "probeTimeoutMs": 8000,
  "totalBudgetMs": 20000,
  "keylessProviders": [         // 追加自己的免 key 接口
    { "id": "mybox", "name": "同事的 llama.cpp", "baseURL": "http://192.168.1.9:8080/v1", "models": ["qwen3-coder"] }
  ],
  "customProviders": [          // 需要 key 的中转站（keylessOnly=false 时才会用）
    { "id": "relay", "baseURL": "https://relay.example.com/v1", "apiKeyEnv": "RELAY_API_KEY", "freeModels": ["glm-4.6"] }
  ]
}
```

### 想改用需要 key 的免费来源

1. 在 opencode 里 `/connect` 登录（或用 `OPENCODE_API_KEY` / `ZHIPU_API_KEY` 等环境变量）；
2. 把 `data\model-policy.json` 的 `keylessOnly` 改成 `false`；
3. 下次启动就会在 OpenCode Zen（33 个免费模型）、智谱、ModelScope、iFlow、OpenRouter 等来源里自动挑选。

## 五、常见问题

**Q：双击后没有任何反应，或控制台一闪就没了？**
A：v1.1.2 起不会再有"无声退出"：
- 构建失败 → 控制台停住等你按回车，日志尾部写进窗口，同时启动器弹对话框说明原因；
- 构建器被安全软件拦住根本没起来 → 启动器等 8 秒后会弹"安装未能启动"的对话框；
- 安装进行中再次双击 → 弹"正在安装中"提示，不会重复下载。

排查用 `OpenCode-debug.cmd`（会启动程序并把 `launcher.log`、`build.log` 尾部打印在窗口里），
或直接看 `data\build.log`、`data\build-state.json`。

**Q：出现 `'"D:\...\Build portable version.cmd"' 不是内部或外部命令`？**
A：这是 v1.1.0 的缺陷。v1.1.1 修掉了调用方式，v1.1.2 更进一步——启动器**完全不再调用 .cmd**，
直接启动构建器 exe，这类批处理问题不会再出现。请使用本包内的新版 `OpenCode-Portable.exe`。

**Q：提示"模型不可用 / 请求失败"怎么办？**
A：不用自己改配置：启动器每次启动都会重新体检并自动切换到能用的**免 key** 免费模型，结果看 `data\models-report.json`。
若显示"没有找到免 key 的免费模型来源"，说明内置公开接口当前不可用（多为限流）：可以稍后重试、启动本机 Ollama 后再用，
或把 `keylessOnly` 改成 `false` 使用需要 key 的来源。想固定某个模型写 `pinnedModel`；不想让它自动改就写 `"autoSwitch": false`。

**Q：公共免 key 接口被限流了怎么办？**
A：装上 Ollama（`ollama pull qwen3-coder:30b`）后重新启动，启动器检测到本机服务会优先使用它，不再依赖公共额度。

**Q：构建时报网络错误？**
A：v1.1.2 会自动依次尝试：系统代理 → 直连 → 公共镜像。仍失败时可离线安装：
```
set OPENCODE_BUILDER_ARGS=--installer "D:\opencode-desktop-win-x64.exe"
"Build portable version.cmd"
```
或用某个具体版本重建：
```
set OPENCODE_BUILDER_ARGS=--version v1.18.31
```

**Q：提示某个补丁不匹配？**
A：说明该 opencode 版本的代码变了。用已验证版本重建即可：
`tools\OpenCode-Portable-Builder.exe --update --version v1.18.31`

**Q：U 盘空间不够？**
A：首次构建需要约 2 GB 空闲；构建完成后安装包缓存（`data\cache\build\`）可以删掉，能省 120 MB+。

**Q：怎么确认代理生效了？**
A：看 `data\launcher.log` 里的 `HTTP_PROXY`/`HTTPS_PROXY` 一行（写明来源），
或 `data\build.log` 里的"网络代理"一行（写明"来源：环境变量 HTTPS_PROXY / Windows 系统代理设置"）。

**Q：想完全不用 exe？**
A：`OpenCode-debug.cmd` 也会启动程序并在控制台显示日志；`tools\7za\7za.exe` 也可单独用来解包。

## 六、技术说明（给想深挖的人）

- 便携化不是"安装到 U 盘"，而是把官方 Electron 应用的 `resources\app.asar` 做**二进制级重建**：
  注入 `out/main/opencode-portable-boot.js`（启动前重定向所有可写路径 + 残留台账），并修改主进程 4 处代码（关自动更新、userData/sessionData 走 U 盘、不注册协议）。
- 注入模块是以 ESM 形式被主进程 `import` 的独立文件；它自带 `import { app } from "electron"` 与
  `import { spawnSync } from "node:child_process"`（v1.1.2 修复）——否则在 `try/catch` 里会静默失效。
- 补丁器会重新计算每个文件的 `integrity`（SHA256 / 4 MB 分块），保持与官方归档一致的格式。
- 已做的实测（Wine 10 模拟 Windows，含真实网络）：
  1) 缓存构建 19 秒、联网构建 20–24 秒完成，应用目录与 `data\` 树结构正确；
  2) 系统代理（注册表 `ProxyEnable`/`ProxyServer`）→ 启动器识别并导出 → 构建器经代理下载成功（代理端可见 CONNECT 记录）；
  3) 故意用损坏安装包 → 状态 `failed` + 弹窗 + 日志留存，退出码非 0；
  4) 安装中重复双击 → 第二次被拒绝，全程只有一次下载；
  5) 把 github.com 指向黑洞模拟"被墙" → 自动改走公共镜像后构建成功，SHA-256 与官方 digest 一致；
